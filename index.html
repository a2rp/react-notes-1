React

React is an open-source JavaScript library for building user interfaces from components. The React project is owned by the React Foundation, hosted by the Linux Foundation, and developed by its maintainers and open-source contributors. React can power web interfaces, server-rendered apps through frameworks, and native apps with React Native. React focuses on the UI; routing, data loading, and deployment are provided by frameworks or other libraries.

Why do we use React?

React lets developers describe a user interface as components derived from props and state. When those values change, React renders the updated UI and reconciles the result with the DOM. This model supports reusable components and predictable data flow; it does not guarantee that every React app is faster than a hand-written DOM implementation.

React Version History

  • Jordan Walke developed an early version of React at Facebook before it was shared publicly.
  • React was open-sourced at JSConf US in May 2013. It is a JavaScript library, not a programming language.
  • React Native was announced in 2015 as a way to build native mobile interfaces with React.
  • React 16.8 introduced Hooks in 2019, allowing function components to use state and other React features.
  • React 17, released in 2020, focused on making gradual upgrades easier and added no new developer-facing features.
  • React 18 was released in March 2022. It introduced the new root API and concurrent rendering features, including automatic batching.
  • React 19 became stable in December 2024. It added Actions, resource APIs, and Hooks such as useActionState and useOptimistic. See the React 19 release notes.
  • React 19.2 arrived in October 2025 with <Activity>, useEffectEvent, and React Performance Tracks. Read the React 19.2 announcement.
  • The React Foundation launched in February 2026 under the Linux Foundation. React and related projects moved from Meta to this independent foundation; technical direction remains with React maintainers. Read the foundation announcement.
  • React 19.3 arrived in September 2026. It made View Transitions and Fragment Refs stable and added React DOM support for browser() and Trusted Types. See the React 19.3 announcement.

Starting a React project

React is a UI library; a complete application also needs decisions about routing, data loading, rendering, and deployment. For most new production apps, the React team recommends starting with a framework. If a client-only app or a learning project is a better fit, a build tool such as Vite is a practical starting point. Create React App was deprecated for new apps in February 2025 and is now in maintenance mode. Read the React team's Create React App announcement and the guide to building an app from scratch.
  • Install a currently supported Node.js release from the official downloads page. Check the version with node --version and npm --version.
  • Create and run a Vite React app: 
    npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
    Vite prints the local development URL in the terminal.
  • Create the optimized production bundle with npm run build. Use npm run preview to preview that bundle locally.

Features of React

  • Declarative UI written as components.
  • Props and state for passing data and describing changing UI.
  • Composition for building larger interfaces from smaller components.
  • Hooks for state and other React features in function components.
  • JSX as an optional, commonly used syntax for writing UI.
  • Renderers such as React DOM for the browser and React Native for native apps.

React trade-offs

  • React focuses on UI. Apps choose their own routing, data-fetching, and build tools unless a framework provides them.
  • JSX and many modern React patterns rely on a build step, though React can also be added to an existing page.
  • Component boundaries and shared state still need careful design as an app grows.

React JSX

Function components return UI; class components return UI from their render method. JSX is an optional JavaScript syntax for describing that UI with markup-like expressions. A build tool transforms JSX into JavaScript that React can render. 
            JSX File
            <div>Hello JavaTpoint</div>
            
            Corresponding Output
            React.createElement("div", null, "a2rp: an Ashish Ranjan presentation");

Nested Elements in JSX

To use more than one element, we need to wrap it with one container element. 
            import React, { Component } from 'react';
            class App extends Component {
                render() {
                    return (
                        <div>
                            <h1>a2rp: an Ashish Ranjan presentation</h1>
                            <h2>Training Institutes</h2>
                            <p>This website contains the best CS tutorials.</p>
                        </div>
                    );
                }
            }
            export default App;

JSX Attributes

JSX use attributes with the HTML elements same as regular HTML. JSX uses camelcase naming convention for attributes rather than standard naming convention of HTML. A class in HTML becomes className in JSX because the class is the reserved keyword in JavaScript. We can also use our own custom attributes in JSX. For custom attributes, we need to use data- prefix. 
            <p data-demoAttribute = "demo">
                a2rp: an Ashish Ranjan presentation
            </p>
In JSX, we can specify attribute values in two ways:
  1. as string literals 
    const element = <h3 className = "firstAttribute">a2rp</h3>;
  2. as expressions 
    const element = <h3 className = "firstAttribute">{30*40}/h3>;

JSX Comments

JSX allows us to use comments that begin with /* and ends with */ and wrapping them in curly braces {} just like in the case of JSX expressions. 
{/*this is a comment in jsx*/}

JSX Styling

React Components

The component-based approach was introduced to overcome the issue of traditional DOM structure. In this approach, the entire application is divided into a small logical group of code, which is known as components. A Component is considered as the core building blocks of a React application. It makes the task of building UIs much easier. Each component exists in the same space, but they work independently from one another and merge all in a parent component, which will be the final UI of our application. Every React component has its own structure, methods as well as APIs. They can be reusable as per our need. In ReactJS, we have mainly two types of components. They are
  • Function Components: A function component is a JavaScript function that receives props and returns UI. It can also use Hooks such as useState and useReducer to manage state. Function components are the usual choice for new React components. 
                        function Greeting({ name }) {
                        return <h1>Welcome, {name}</h1>;
                    }
  • Class Components: Class components extend React.Component and implement a render method. They can hold state and define lifecycle methods. React still supports them, though function components are generally used for new code. 
                        class MyComponent extends React.Component {
                        render() {
                            return (
                                <div>This is main component.</div>
                            );
                        }
                    }

React State

State is data a component remembers between renders. In function components, useState returns the current state snapshot and a setter; in class components, state is updated with setState. Setting state requests a new render. Treat objects and arrays in state as immutable: create an updated value instead of changing the existing one. 
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(value => value + 1)}>{count}</button>;
}

React Props

Props are read-only inputs passed by a parent to a component. They can contain values such as strings, objects, functions, or React elements. A component should not mutate its props; a parent can pass new values when it renders again. Props work much like function arguments.

Default Props

Give function component props JavaScript defaults in the parameter list. For example: 
function Greeting({ name = "Guest" }) {
  return <p>Hello, {name}!</p>;
}
A default is used when a prop is undefined; an explicit null value is kept.

State and Props

It is possible to combine both state and props in our app. We can set the state in the parent component and pass it in the child component using props.

State vs Props

State

State is information a component remembers between renders. A state setter requests an update; treat objects and arrays in state as immutable and create a new value when something changes.

Props

Props are read-only inputs supplied by a parent. They describe what a component should render; local changes belong in state or in the parent that owns the value.

Rendering to the DOM

A client-rendered app creates a root for a browser DOM element and renders its root component there. Most apps need one root. A server-rendered page uses hydrateRoot instead so React can attach to the HTML that is already on the page. 
import { createRoot } from "react-dom/client";
import App from "./App";

const root = createRoot(document.getElementById("root"));
root.render(<App />);

Class Component Lifecycle

Class components expose lifecycle methods for work tied to mounting, updating, and removal from the screen:
  • componentDidMount runs after the component is added to the screen.
  • componentDidUpdate runs after an update is committed.
  • componentWillUnmount runs before the component is removed.
Function components use Effects to synchronize with external systems. Effects are not a one-to-one replacement for class lifecycle methods; use them for a specific synchronization process and clean it up when that process ends.

React Forms

Forms are an integral part of any modern web application. It allows the users to interact with the application as well as gather information from the users. Forms can perform many tasks that depend on the nature of our business requirements and logic such as authentication of the user, adding user, searching, filtering, booking, ordering, etc. A form can contain text fields, buttons, checkbox, radio button, etc.

Creating Form

React offers a stateful, reactive approach to build a form. The component rather than the DOM usually handles the React form. In React, the form is usually implemented by using controlled components.

There are mainly two types of form input in React.

  • Uncontrolled

    We need to use a ref to get form values from the DOM. There is no need to write an event handler for every state update. We can use a ref to access the input field value of the form from the DOM.

  • Controlled

    In this, the input form element is handled by the component rather than the DOM. Here, the mutable state is kept in the state property and will be updated only with setState() method. Controlled components have functions that govern the data passing into them on every onChange event, rather than grabbing the data only once, e.g., when we click a submit button. This data is then saved to state and updated with setState() method. This makes component have better control over the form elements and data. A controlled component takes its current value through props and notifies the changes through callbacks like an onChange event. A parent component "controls" this change by handling the callback and managing its own state and then passing the new values as props to the controlled component. It is also called as a dumb component.

React Events

An event is an action that could be triggered as a result of the user action or system generated event. For example, a mouse click, loading of a web page, pressing a key, window resizes, and other interactions are called events. React has its own event handling system which is very similar to handling events on DOM elements. The react event handling system is known as Synthetic Events. The synthetic event is a cross-browser wrapper of the browser's native event. Handling events with react have some syntactic differences from handling events on DOM. These are:
  • React events are named as camelCase instead of lowercase.
  • With JSX, a function is passed as the event handler instead of a string.
  • In react, we cannot return false to prevent the default behavior. We must call preventDefault event explicitly to prevent the default behavior.

React Conditional Rendering

In React, conditional rendering works the same way as the conditions work in JavaScript. We use JavaScript operators to create elements representing the current state, and then React Component update the UI to match them. There is more than one way to do conditional rendering in React. They are given below.
  • if
  • ternary operator
  • logical && operator
  • switch case operator
  • Conditional Rendering with enums

React Lists

Lists are used to display data in an ordered format and mainly used to display menus on websites. In React, Lists can be created in a similar way as we create lists in JavaScript. The map() function is used for traversing the lists.

React Keys

A key is a unique identifier. In React, it is used to identify which items have changed, updated, or deleted from the Lists. It is useful when we dynamically create components or when the user alters the list. It also helps to determine which components in a collection needs to be re-rendered instead of re-rendering the entire set of components every time. The best way to pick a key as a string that uniquely identifies the items in the list.

React Fragments

Fragments group sibling elements without adding a wrapper element to the DOM. Use them when the surrounding layout does not need another element. When a fragment is returned from a list, use the explicit React.Fragment form to provide its key; shorthand fragments do not accept a key. 
            <React.Fragment>  
                <h2> child1 </h2>   
                <p> child2 </p>   
                .. ..... .... ...  
            </React.Fragment>  

            short hand syntax
            <>  
                <h2> child1 </h2>   
                <p> child2 </p>   
                .. ..... .... ...  
            </>
We need a key for mapping a collection to an array of fragments such as to create a description list. If we need to provide keys, we have to declare the fragments with the explicit <React.Fragment key={item.id}> syntax. Key is the only attributes that can be passed with the Fragments. The shorthand syntax does not accept key attributes.

React Router

A router maps URL paths to views and handles navigation. React can render multiple views without a routing library, but a router provides route matching, links, nested routes, and browser history integration. The current declarative React Router API is available from the react-router package: 
npm install react-router

Wrap the routes in BrowserRouter; use Routes and Route to match paths, Link for navigation, and Navigate for redirects.

import { BrowserRouter, Link, Navigate, Route, Routes } from "react-router";

// Home, About, and NotFound are components defined elsewhere.
function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/about">About</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/old" element={<Navigate to="/about" replace />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  );
}

BrowserRouter and HashRouter

BrowserRouter uses the History API and clean paths. A static host must serve the app entry point for nested URLs. Use HashRouter when the host cannot be configured to do that; it keeps the route after a # in the URL.

Nested routes

Nested routes let a parent layout render matching child routes through Outlet. React Router v6 examples may import from react-router-dom; v7 and newer examples use react-router.

React Styling

Use className and CSS for most styling. The style prop accepts a JavaScript object with camel-cased property names and is useful for small sets of dynamic inline styles. React does not prescribe a styling system; common options include CSS files, CSS Modules, Sass, utility classes, and CSS-in-JS libraries.
  • Inline Styling
  • CSS Stylesheet
  • CSS Module
  • Styled Components

JavaScript Map

Map is a JavaScript collection of key-value pairs. Each key is unique, and keys can be values of any type. In React, use Array.prototype.map to turn an array of data into a list of elements, and give each element a stable key prop.

Tables in React

Use semantic HTML table elements when the content is tabular data: table, thead, tbody, tr, th, and td. React renders these elements and their data-driven rows as JSX. For sorting, filtering, pagination, or other data-grid features, choose a maintained table library that fits the project rather than treating a table as a built-in React feature.

Higher-Order Components

A higher-order component (HOC) is a function that receives a component and returns an enhanced component. It is a reuse pattern, not a built-in React API. HOCs remain useful in some libraries, while composition and custom Hooks are often simpler choices for sharing behavior in new components.

Code Splitting

Code splitting lets a build tool create smaller JavaScript chunks that can be loaded when needed. React's lazy can defer loading a component, and Suspense can show a fallback while it is loading: 
            ...
            const ExampleComponent = React.lazy(() => import('./ExampleComponent')); 
            ...
            <Suspense fallback={<div>Loading...</div>}>
            ...
            </Suspense>
            ...
The fallback prop accepts the UI to show while the lazy component loads. A lazy component is declared with a default export; a small wrapper can re-export a named component as the default.

Error boundaries

If any module fails to load, for example, due to network failure, we will get an error. We can handle these errors with Error Boundaries. Once we have created the Error Boundary, we can use it anywhere above our lazy components to display an error state.

Named Export

Currently, React.lazy supports default exports only. If any module we want to import using named exports, we need to create an intermediate module that re-exports it as the default.

React Context

Context lets a component provide a value to descendants without forwarding it through every intermediate component. Create a context, place a provider above the components that need it, and read the value with useContext. Use context for values shared across a part of the tree, such as a theme or current account; ordinary props are simpler when only a nearby child needs the value.

React Hooks

Hooks let function components use React features such as state, context, refs, and Effects. Hooks were introduced in React 16.8. Call them only at the top level of a function component or a custom Hook, never inside conditions, loops, event handlers, or class components.

Rules of Hooks

  • Only call Hooks at the top level
  • Only call Hooks from React functions

State with Hooks

useState stores a value between renders and returns a setter that requests an update. Use useReducer when state transitions are easier to describe with a reducer function.

Effects

useEffect synchronizes a component with an external system after a render, such as a subscription, timer, browser API, or third-party widget. Return a cleanup function when that connection needs to be stopped. For derived values or logic caused by a user action, calculate during rendering or use an event handler instead of adding an Effect.
  • Connect and disconnect a subscription.
  • Start and clear a timer.
  • Synchronize a non-React widget with current props or state.

Custom Hooks

A custom Hook is a JavaScript function. The name of custom Hook starts with "use" which can call other Hooks. A custom Hook is just like a regular function, and the word "use" in the beginning tells that this function follows the rules of Hooks. Building custom Hooks allows us to extract component logic into reusable functions.

React Flux

Flux is a client-side application architecture introduced by Facebook. It describes one-way data flow: actions describe changes, a dispatcher routes them, stores hold application state, and views render that state and emit actions. Flux is an architecture pattern, not a React feature or a guarantee against runtime errors. Redux is a separate library that uses related unidirectional data-flow ideas.
  • Dispatcher
  • Stores
  • Views (React components)

Redux with React

Redux is a state-management library that can be used with React or other UI layers. For React apps, Redux Toolkit is the recommended way to set up a store and write reducers; React-Redux connects the store to React components. Redux is useful when shared application state needs a central update model, but local component state is enough for many UI needs. See the Redux Toolkit usage guide.
  • Store: holds the current application state.
  • Action: describes an event or requested change.
  • Reducer: calculates the next state from the current state and an action.
  • Selector: reads or derives data from the store.
